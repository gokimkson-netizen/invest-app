# M4 무한매수법 계산 엔진(Core) 입출력 스키마

코드: `packages/core/src/infinite/core.ts` (공개, D1). **규칙 값(문서에서 옮긴 비율·기울기·분모·한도)은 이 저장소에 없다.** 규칙 파일은 내 PC의 `private/infinite_v4.rules.json`과 각 기기 IndexedDB(암호화 동기화)에만 있다. `check_repo.py`가 규칙 파일의 `필드: 값` 쌍이 공개 파일에 없는지 검사한다.

## 현재 상태
- 사용자 문서(V4.0 강의자료)를 받아 규칙 종류 17개를 등록했고, 규칙 파일(규칙 24개)·대응표·문서 예시 테스트(22건)를 `private/`에 만들었다.
- 규칙 ID 일치와 문서 예시 테스트는 `python scripts/check_infinite_mapping.py`(로컬 전용)로 검사한다. 공개 저장소에는 결과 요약(일치 여부·해시)만 남긴다.
- 규칙 파일을 불러오지 않은 기기에서는 "규칙 미입력 — 무한매수법 문서 필요"만 표시한다.

## 규칙 종류(구조만)
| 종류 | 필드 | 계산 |
|---|---|---|
| BUY_AMOUNT | — | 1회매수금 = 잔금 ÷ (분할수 − T) |
| STAR_LINEAR | 종목, 분할수, 시작값, 기울기 | 별% = 시작값 − 기울기 × T |
| STAR_POINT | 자릿수 | 별지점 = 평단 × (1 + 별%), 반올림 |
| BUY_OFFSET | 값 | 매수점 = 별지점 − 값 |
| FIRST_BUY | 할증최소%, 할증최대% | 첫 매수: 전일 종가 × (1 + 할증), 할증은 범위 안에서 사용자가 입력 |
| PHASE | 경계비율, 전반전분할비율 | 전반전(T < 분할수 × 경계비율): 1회매수금을 나눠 매수점·평단에, 후반전: 전액 매수점에 |
| LADDER | 사다리수량 | 사다리 가격 = 1회매수금 ÷ (누적 수량 + k), 내림, 주문가보다 낮은 것만. **개수는 사용자 입력** |
| QUARTER_SELL | 비율 | 보유 × 비율(내림) → 별지점 LOC 매도 |
| TARGET_SELL | 종목, 목표% | 나머지 → 평단 × (1 + 목표%) 지정가 매도 |
| T_UPDATE | 전량매수, 절반매수, 쿼터매도배수, 목표매도배수 | 매도 배수 먼저 곱하고 매수 가산. 보유 0이면 T = 0(사이클 종료) |
| REVERSE_TRIGGER | 여유회차 | T > 분할수 − 여유회차 → 리버스 모드 |
| REVERSE_STAR | 이동평균일수 | 리버스 별지점 = 최근 N거래일 종가 평균 |
| REVERSE_SELL | 분할수, 매도분모 | 첫날 MOC, 이후 별지점 LOC: 보유 ÷ 분모(내림) |
| REVERSE_BUY | 잔금분모 | 둘째 날부터 잔금 ÷ 분모 → 매수점 LOC |
| REVERSE_T | 분할수, 매도배수, 매수비율 | 매도: T × 배수, 매수: T + (분할수 − T) × 비율 |
| REVERSE_EXIT | 종목, 하락한도% | 둘째 날부터 종가 > 평단 × (1 − 한도) → 일반 모드(T 승계) |
| QTY_ROUNDING | 방식 | '내림'만 지원 |

## 입력
```json
// PositionState(종목별 독립 원금, 40분할)
{ "종목": "TQQQ|SOXL", "원금": 0, "분할수": 40, "회차": 0, "누적매수금": 0, "보유수량": 0, "잔금": 0,
  "모드": "일반|리버스", "리버스일차": 0, "사이클": 1, "체결": [{ "일자": "YYYY-MM-DD", "구분": "매수|매도", "수량": 0, "가격": 0, "역할": "first|buy_star|..." }] }
// RuleFile
{ "버전": "", "작성일": "YYYY-MM-DD", "DUMMY": false, "규칙": [{ "규칙ID": "", "문서쪽번호": "", "종류": "<위 표>", "...필드": "값" }] }
// MarketInput / UserOptions
{ "기준일": "YYYY-MM-DD", "전일종가": 0, "최근종가": [0] }   { "첫매수할증%": null, "사다리개수": null }
```
## 출력
```json
{ "상태": "정상|규칙 미입력|규칙 오류|DUMMY 차단|입력 필요|가격 데이터 부족", "메시지": "",
  "주문": [{ "종류": "", "역할": "", "구분": "매수|매도", "주문유형": "LOC|MOC|지정가", "가격": 0, "수량": 0, "규칙ID": "" }],
  "정보": { "구간": "첫 매수|전반전|후반전|리버스|리버스 종료(일반 복귀)", "회차": 0, "1회매수금": 0, "별%": 0, "별지점": 0, "매수점": 0, "평단": 0, "잔금": 0, "참고": [] } }
```
## 함수
| 함수 | 설명 |
|---|---|
| `validateRuleFile(x, {allowDummy})` | 버전·작성일·규칙ID 중복·문서쪽번호·등록 종류·필드 형식·필요한 종류 모두 있는지. 기본값 없음 |
| `plan(state, rules, market, {user})` | 규칙이 없거나 검증 실패·필요 입력 없음이면 주문 0건 |
| `settleDay(state, rules, plan, fills)` | 그날 체결(역할 포함)을 반영해 평단·보유·잔금·회차·모드를 규칙대로 갱신 |
| `newCycle(state, 원금)` | 사이클 종료 뒤 새 원금(복리·단리는 사용자가 고름) |
| `applyFills`·`setRound` | 수동 기록·수정(규칙 갱신 없음) |

- 테스트용 `DUMMY` 파일은 실제 계산 화면(`allowDummy=false`)에서 차단된다. 공개 테스트(`infinite.test.ts`)는 문서와 다른 임의의 DUMMY 값으로 구조만 검증한다.
- 주문 거부 대응(문서의 예외 절차)은 증권사 응답에 따른 수동 절차라 계산하지 않고 화면에 안내만 한다.
- PC 자동매매 프로그램은 같은 규칙 파일을 로컬에서 읽고 이 모듈(번들)을 그대로 쓴다. 런타임에 코드 파일을 불러와 eval로 실행하는 방식은 금지(CSP·XSS 방어).
